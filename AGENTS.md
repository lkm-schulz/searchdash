# searchdash

Read-only live web dashboard for per-iteration experiment artifacts — autoresearch-style runs, OpenEvolve-style evolutionary search, or any harness emitting per-iteration records. Single instance serves every datadir under a root, selectable via home picker or bookmarkable `?datadir=` URLs (root-relative paths). Charts metric progressions, lists every iteration with metrics, drills into markdown/diff/code detail, builds ad-hoc scatter plots, renders the iteration DAG. Never writes.

Two layers: **Python backend** (`searchdash/`, ~700 LOC) resolves datadir per-request + serves a read-only `/api`; **React SPA** (`frontend/`) polls that API and renders. Prod = one uvicorn process serving API + prebuilt `dist/`; dev = API thread + Vite HMR proxying `/api`.

`README.md` is the prose reference (**read first for *why* + the on-disk contract**). The schema's source of truth is the pydantic models in `datadir.py`. This file is the nav layer: subsystem → doc/source.

## Lab Notes

Log failed approaches / dead ends here.

- **`index.html` must stay uncached** (`Cache-Control: no-store` in `server.py:_mount_spa`). It references content-hashed asset names; caching it pins the browser to a stale build whose assets 404 after a rebuild.
- **First prod run needs `npm`** — builds `frontend/dist/` (and `npm install` if `node_modules` absent). `--rebuild` forces it; dev mode (`--dev`) never uses `dist/`.
- **Every API read re-scans the datadir** (no caching — payloads small). Don't add caching without a reason; live polling depends on fresh reads.
- **HTTP keep-alive disabled** (`timeout_keep_alive=0` in `launcher.py` uvicorn calls, `keepAliveTimeout=1` via Vite plugin in `frontend/vite.config.ts`). After stop/restart on same port, pooled keep-alive sockets are dead; browser reuses them → 30s stall before retry. Disabling keep-alive forces fresh connections.
